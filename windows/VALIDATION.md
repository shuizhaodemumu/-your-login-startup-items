# Windows 1.0.0 验证范围

验证日期：2026-11-24。实现与构建由 Codex 完成；Gemini 3.8 Flash High 通过登记执行器选择测试、分析实际日志并形成独立验收报告。

| 测试 | 结果 | 范围 |
| --- | --- | --- |
| Rust 单元测试 | 5 项通过 | 连续卡顿计时、恢复响应清零、休眠间隔、FFI 布局与路径匹配 |
| 原生集成测试 | 28 项断言通过 | 快捷方式与参数、真实进程启动/退出、无响应重启、子进程清理、窗口与最大化/最小化恢复、暂停、防重复接管、崩溃保护、配置回退 |
| UI 与托盘测试 | 15 项断言通过 | FileDrop 回调、列表和开关、移除、隔离配置保存、NotifyIcon 生命周期、托盘菜单、后台启动参数与退出保留目标 |

Gemini 复验的两组集成测试退出码均为 0。持续卡死夹具在约 **10.41 秒**后被结束并重启，3.5 秒短暂卡顿没有触发重启。

发布程序在 Windows 上实际启动并完成界面检查；发布包内 EXE 与 DLL 的 SHA-256 与已测试构建一致。素材采用透明 PNG，欢迎、守护、修复三个状态均已检查。

## 未覆盖

- 真实注销、开机登录和整机重启；只验证 `--startup` 的后台启动代码路径。
- 管理员/UIPI 跨权限场景。
- 物理鼠标拖放；测试使用实际 Windows FileDrop 数据对象派发界面事件。
- 多显示器热插拔和不同 DPI 之间的动态切换。
- Chromium/Electron、更新器、启动器等第三方程序的长期兼容性。

夹具运行在真实 Windows 环境中，隔离的是测试进程与数据，不是声称覆盖了全部应用。没有对用户正在使用的真实软件进行强杀测试。

## 对验收建议的实现核对

已有滑动时间窗口和 Job Object，无需改成固定分钟计数；退出软件时刻意不启用 KILL_ON_JOB_CLOSE，以保留目标程序运行。窗口恢复使用 `SetWindowPlacement`，系统对完全屏幕外的位置提供可见性调整，但跨 DPI 场景仍保留未测试声明。管理员拖放受限时已有文件选择器入口。

第二轮修复了暂停看门狗后状态快照未即时更新的问题，并补充了最大化/最小化、无窗口程序和托盘流程的测试覆盖。
